# Unity C# best practices

Updated: 2026-10-02. Read before writing or changing Unity C# code, together with the general C# best practices. Follow coherent project-specific rules.

- **Compatibility:** Use syntax and APIs supported by the exact Editor, packages, and target platform. Do not introduce newer language features as a style cleanup.
- **Fields:** Constants, static fields, serialized references, serialized settings, dependencies/caches, then runtime state. Group by gameplay purpose, not alphabetically or by type. Keep required references before optional ones and main settings before dependent values. Separate groups with one blank line; preserve initializer dependencies.
- **Inspector:** Use private `[SerializeField]` fields in camelCase without underscores. Put attributes on separate lines. Use meaningful `[Header]` groups; add tooltips only for unclear units or behavior. Expose deliberate operations or read-only properties instead of public mutable fields.
- **Custom Inspectors:** Create or maintain an Editor-only custom Inspector for serialized components and assets with authoring controls. Group related fields into clear sections with readable labels, spacing, and units; use foldouts for secondary settings and keep common controls visible. Prefer standard Unity controls over decorative UI. Keep Inspector code in an `Editor` folder or Editor-only assembly, with no `UnityEditor` dependency in runtime builds. Edit through `SerializedObject`/`SerializedProperty` to preserve Undo, prefab overrides, and multi-object editing. Verify edits persist, Undo works, and the layout is readable in the Inspector.
- **Members:** Fields, properties/events, Unity callbacks, public operations, then private helpers. Callback order: `Awake`, `OnEnable`, `Start`, update callbacks, `OnDisable`, `OnDestroy`, then other callbacks. Include only needed callbacks; keep setup and cleanup easy to pair.
- **Clarity:** Name units and coordinate spaces where ambiguous. Keep callbacks readable; extract meaningful gameplay operations without adding trivial wrappers. Apply general C# spacing, braces, naming, and sparse-comment rules.
- **Ownership:** Make dependencies, initialization, state ownership, and cleanup explicit. Separate authored configuration from runtime state. Keep Editor code separate from runtime code; add abstractions only for a demonstrated need.
- **Serialization:** Treat scenes, prefabs, and Inspector assignments as code dependencies. Preserve serialized values during field renames using the project's migration approach, including `FormerlySerializedAs` where appropriate. Preserve asset/metadata pairs during moves.
- **Finish:** Format and inspect changed code, verify Unity compilation and relevant behavior, and check affected serialized assets. Keep broad style or Inspector reordering separate from behavior fixes.
