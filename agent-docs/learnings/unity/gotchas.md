# Unity implementation gotchas

Updated: 2026-10-02

## Recording rule

Add entries only for problems or surprising behavior encountered during actual Unity coding or implementation work. Research, hypothetical pitfalls, note queries, and documentation organization do not qualify. Keep these entries here rather than distributing them through best practices or other topic notes.

Each entry should be a short, self-contained dated section naming the symptom. Record the project, relevant Editor/package version, task and reproduction, observed result, confirmed cause or labeled hypothesis, correction/workaround, and checks actually performed. An observed problem may be recorded before its cause is confirmed; clearly mark unresolved causes and unverified fixes. Update the same entry as evidence changes.

### 2026-10-02: Saving additive scene migration and restoring a backup

Project: FirstLight; Unity 6000.3.20f1. During an actual five-scene split, creating a second untitled additive scene failed while the first new scene was unsaved. Save each newly created empty scene to its intended asset path before creating the next. OpenScene also rejected a recovery snapshot stored under Tools, outside Assets. Preserve the live dirty scene with SaveScene(saveAsCopy: true), copy the recovery snapshot into a temporary Assets scene, import it, open it and save back to the original path when recovery is needed. Delete the temporary imported asset after recovery. This preserved the existing scene identity and unsaved terrain/water/prop edits. The final five saved scenes were clean and passed DetectCrossSceneReferences with preventCrossSceneReferences enabled. Status: workaround validated in this migration; use live Editor APIs for scene changes rather than editing YAML.
