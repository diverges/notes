# Natural technical writing

Researched: 2026-09-26
Status: Published editorial guidance, adapted to personal preferences.

Google recommends a conversational but professional tone, concrete language, and avoiding repeated sentence openings. Reading text aloud can expose awkward phrasing. Microsoft recommends putting the main point first, using familiar language, and sentence-case headings.

For this knowledge base, use paragraphs to explain ideas and bullets where items need to be scanned individually. Keep requirement and task lists. Separate heading IDs from titles with a colon, for example `UC.1: Save a draft`. Prefer periods or commas over frequent em dashes.

The punctuation preference is personal, not a claim that dashes identify AI writing. The aim is readable prose, not simulated human authorship. Sources are background only; the working rules are recorded in AGENTS.md.

## Self-contained knowledge notes

Explain the finding, why it matters, and when it applies in the note itself. Include a short example when it makes the idea clearer. Do not ask readers to visit a website for the essential explanation.

Use concise sections that can be read independently. Remove repeated conclusions and narration about reviewing sources. Retain dates, versions, uncertainty, and tradeoffs that affect how the advice should be used. Put website links only in a final `References` section; use local links for table-of-contents navigation.
